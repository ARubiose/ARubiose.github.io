# SEO e i18n del despliegue: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que `/` y `/en/` se indexen bien: `canonical`, `hreflang`, sitemap con alternativas, `robots.txt` y un JSON-LD `Person` derivado de la wiki pública (issue #1).

**Architecture:** La lógica vive en funciones puras de `src/lib/seo.ts` (alternativas, `Person`, `robots.txt`, serialización segura). `HomePage.astro`, que ya carga las colecciones, calcula URLs absolutas y pasa `alternates` y `jsonLd` a `Layout.astro`, que solo escribe el `<head>`. El sitemap lo genera la integración oficial `@astrojs/sitemap` con los mismos códigos de idioma (`localeTags` en `src/i18n/ui.ts`). El esquema de `education` gana `kind: degree | certificate` para separar `alumniOf` de `hasCredential`.

**Tech Stack:** Astro 7.3, `@astrojs/sitemap` 3.7, Zod (`astro/zod`), TypeScript 6, Vitest, Playwright, pnpm 12, Node 24.

**Spec:** [docs/superpowers/specs/2026-10-05-seo-i18n-design.md](../specs/2026-10-05-seo-i18n-design.md).

## Global Constraints

- Antes de cualquier comando de Node: `source ~/.nvm/nvm.sh && nvm use` (la shell trae Node 18).
- Comandos: `pnpm check`, `pnpm test`, `pnpm test:e2e`. Para un e2e suelto: `pnpm exec playwright test tests/e2e/<archivo> --project=desktop` (construye el sitio solo).
- Códigos de idioma: `es` → `es-ES`, `en` → `en-US`; `x-default` → la URL de `es` (`/`).
- Todo dato sale de `site` (`astro.config.mjs`) y del frontmatter de `wiki/public/`; nada personal escrito en `src/`, `tests/` (salvo el dominio, como los e2e actuales) ni en la configuración.
- El JSON-LD **no** lleva `email`. `sameAs` = `links.linkedin` y `links.github` (nunca `links.source`).
- `kind` de `education`: `"degree" | "certificate"`, opcional, por defecto `"degree"`.
- Sin JavaScript de cliente nuevo. `og-image.png` no cambia.
- Nombres de archivo en inglés; contenido y comentarios en español. Commits en inglés con `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; identidad git personal (comprobar `git config --local user.email` y `commit.gpgsign false`).
- Cambios en `wiki/`: seguir `.claude/rules/wiki.md` (actualizar `updated` y añadir una entrada `schema` a `wiki/private/log.md`, que no se versiona).
- Llamadas a `gh` con `GH_TOKEN=$(gh auth token --user ARubiose)`.

## Review Focus

1. **Misma institución en dos títulos** (dos grados en la misma universidad): `alumniOf` la lista una sola vez. Test unitario en la tarea 3.
2. **Texto de la wiki con `</script>` o `<!--`** en un resumen: no cierra la etiqueta del JSON-LD. Test unitario en la tarea 2.
3. **Sin puesto actual** (todas las experiencias cerradas) o con **dos puestos actuales**: `worksFor` se omite o es una lista; nunca `[]` ni `undefined` serializado. Tests unitarios en la tarea 3.
4. **URLs con y sin barra final**: el `canonical`, el `og:url`, las alternativas y el `<loc>` del sitemap deben ser idénticos carácter a carácter (`/en/`, no `/en`), o Google los trata como páginas distintas. Test e2e en la tarea 5.
5. **`site` ausente** (alguien usa la plantilla y lo borra): error claro en build, no URLs relativas ni `Invalid URL`. Test unitario de `requireSite` en la tarea 2.

```ts
import { defaultLocale, localeTags, locales, type Locale } from "@i18n/ui";

export type AlternateLink = { hreflang: string; href: string };

/** Las URLs del SEO deben ser absolutas: sin `site` no hay forma de construirlas. */
export function requireSite(site: URL | undefined): URL {
    if (!site) throw new Error("Falta `site` en astro.config.mjs: canonical, hreflang, sitemap y JSON-LD necesitan URLs absolutas");
    return site;
}

/** Alternativas por idioma, más x-default apuntando al idioma por defecto. */
export function alternateLinks(urls: Record<Locale, string>): AlternateLink[] {
    return [
        ...locales.map((l) => ({ hreflang: localeTags[l], href: urls[l] })),
        { hreflang: "x-default", href: urls[defaultLocale] },
    ];
}

export function robotsTxt(site: URL): string {
    return `User-agent: *\nAllow: /\n\nSitemap: ${new URL("sitemap-index.xml", site).href}\n`;
}

/** JSON para un <script>: escapa `<` para que ningún texto pueda cerrar la etiqueta ni abrir un comentario. */
export function jsonLdScript(data: object): string {
    return JSON.stringify(data).replace(/</g, "\\u003c");
}
```

```ts
import { localize } from "@i18n/utils";
import type { HomeData } from "./home";

const org = (name: string) => ({ "@type": "Organization", name });
// Un solo valor sin lista; ninguno, campo omitido: schema.org no quiere listas vacías.
const oneOrMany = <T>(items: T[]) => (items.length === 1 ? items[0] : items);

/** JSON-LD Person de la portada, solo con datos públicos de la wiki (sin email). */
export function personJsonLd(data: HomeData, locale: Locale, urls: { url: string; image: string }): Record<string, unknown> {
    const profile = localize(data.profile, locale);
    const current = data.experience.filter((e) => e.data.end === null).map((e) => org(e.data.company));
    const schools = [...new Set(data.education.filter((e) => e.data.kind === "degree").map((e) => e.data.institution))];
    const credentials = data.education
        .filter((e) => e.data.kind === "certificate")
        .map((e) => ({ "@type": "EducationalOccupationalCredential", name: localize(e.data, locale).degree, recognizedBy: org(e.data.institution) }));
    return {
        "@context": "https://schema.org",
        "@type": "Person",
        name: profile.name,
        jobTitle: profile.headline,
        description: profile.summary,
        url: urls.url,
        image: urls.image,
        address: { "@type": "PostalAddress", addressLocality: profile.location },
        sameAs: [profile.links.linkedin, profile.links.github],
        ...(current.length ? { worksFor: oneOrMany(current) } : {}),
        ...(schools.length ? { alumniOf: schools.map((name) => ({ "@type": "CollegeOrUniversity", name })) } : {}),
        ...(credentials.length ? { hasCredential: credentials } : {}),
        ...(data.skills.length ? { knowsAbout: data.skills.map((s) => s.data.title) } : {}),
    };
}
```

(`alumniOf`, `hasCredential` y `knowsAbout` son siempre listas cuando existen: así el test fija una forma estable; `worksFor` usa `oneOrMany` porque lo normal es un único puesto.)
